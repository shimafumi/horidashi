# horidashi

官公庁オークションの出品物件をスプレッドシートに一覧化する Google Apps Script です。
robots.txt を守り、1件ごとに待ち時間を入れてアクセスします。

## 初回セットアップ

1. https://script.google.com/home/usersettings で「Google Apps Script API」をオンにする
2. VS Code でこのフォルダを開き、「Reopen in Container」を選ぶ
3. コンテナ内のターミナルで `clasp login` を実行し、表示されたURLをブラウザで開いて承認する
4. スプレッドシートを新規作成し、「拡張機能 > Apps Script」を開く
5. Apps Script の「プロジェクトの設定」からスクリプトIDをコピーする
6. `cp .clasp.json.example .clasp.json` を実行し、スクリプトIDを書き込む
7. `npm run push` でコードを反映する
8. スプレッドシートを再読み込みすると「公売リスト」メニューが表示される

### `clasp login` で詰まった場合

ログイン後にブラウザで「このサイトにアクセスできません」と表示された場合は、
アドレスバーのURL（`http://localhost:...?code=...` の形）を丸ごとコピーし、
`clasp login` を実行したまま、コンテナ内の別のターミナルで次を実行してください。

```bash
curl "コピーしたURL"
```

ログイン情報はボリュームに保存されるので、コンテナを作り直しても再ログインは不要です。

## 開発

- `npm run push`：ローカルのコードを Apps Script に反映
- `npm run pull`：Apps Script 側の変更をローカルに取り込む
- `npm run watch`：保存するたびに自動で反映

### ファイル構成（`src/`）

Apps Script では全ファイルが同じグローバル空間で動くため、import なしで互いの関数・定数を使えます。

| ファイル | 内容 |
| --- | --- |
| `config.js` | 設定（`CONFIG`）と定数 |
| `main.js` | 一覧の更新処理（連番取得・欠番の再確認） |
| `menu.js` | メニュー、初期設定、HTML確認、通知 |
| `sheet.js` | 一覧シートへの書き込み |
| `trigger.js` | 自動更新のトリガー |
| `fetch.js` | ページ取得と物件あり／欠番の判定 |
| `robots.js` | robots.txt の読み込みと判定 |
| `parser.js` | 物件ページの HTML 解析 |

## 使い方

1. 「公売リスト > ① 初期設定」を実行
2. 「② 一覧を更新」または「自動更新を開始」を実行
   - 物件ID `CONFIG.START_ID` から連番で取得し、続きは次回の実行に引き継ぐ
   - 空ページ・存在しないIDは「欠番」列に印を付けて一覧に残し、`RECHECK_HOURS` ごとに再確認する
   - 欠番と判定した回数は「欠番確認回数」列に残り、`MISSING_CHECK_LIMIT` 回に達した行は再確認しない
     （回数を減らすか空にすると、また再確認の対象になる）
   - 欠番が出たら 1〜`PROBE_RANGE` 先のランダムな物件を `PROBE_COUNT` 回チェックし、
     すべて欠番なら最初の欠番まで取得済みとみなして停止する（自動更新も停止）
3. 入札期間は「入札開始」「入札終了」の2列に日時で入る（日時が読めないときは「入札開始」に元の文字列が入る）
4. 「カテゴリ」列（物件名の右）には物件ページのパンくずリストなどから取ったカテゴリが入る
   - 取れないときは「HTML確認」で実行ログの解析結果（`category`）とページの中身を確認する

`START_ID` を変えたときは「連番取得の位置をリセット」を実行してください（取得済みのIDはスキップされます）。

### メニュー

| メニュー | 内容 |
| --- | --- |
| ① 初期設定 | 「一覧」シートを作り、見出しを書く |
| ② 一覧を更新 | 新しい物件の取得と、欠番の再確認を行う |
| 自動更新を開始 | 物件を最新まで取得し終わるまで一定間隔で自動実行し、最新化後に自動停止する |
| 自動更新を停止 | 自動更新を止める |
| 自動更新状況を確認 | 自動更新トリガーの有効・停止と、現在の設定間隔を表示する |
| 連番取得の位置をリセット | 次回の取得を `START_ID` から始め直す（一覧にあるIDはスキップ） |
| HTML確認（物件IDを指定） | 1件のページを取得し、判定・解析結果・本文を実行ログに出す（取得がうまくいかないときの調査用） |

### 一覧の列

| 列 | 内容 |
| --- | --- |
| 物件ID / URL / 物件名 / 執行機関 | 物件ページから取得 |
| 大分類 / 中分類 / 小分類 | パンくずリストの1つ目・2つ目・残り（`>` でつなぐ）。例：`一般` / `スポーツ、レジャー` / `船、ボート > パーツ` |
| 見積価額等(円) | 見積価額・予定価格など |
| 入札開始 / 入札終了 | 入札期間の日時（公開中止の物件は「入札開始」に「中止」。ほかに読めないときは空） |
| 取得日時 | 最後に取得・確認した日時（秒まで記録） |
| 欠番 / 欠番確認回数 | 欠番の印と、欠番と判定した回数（下記） |

### 取得の仕組み

- 物件ID `START_ID` から連番で取得し、続きは次回の実行に引き継ぐ
- 欠番（空ページ・存在しないID）が出たら、1〜`PROBE_RANGE` 先のランダムな物件を `PROBE_COUNT` 回チェックする
  - 先に物件があれば、欠番として一覧に残して先へ進む
  - すべて欠番なら最新まで取得済みとみなし、今回の取得を終える。
    最新より先の欠番はまだ採番されていないだけの可能性が高いので一覧には書かず、次回その位置から確認し直す
- 一覧に残した欠番は `RECHECK_HOURS` ごとに再確認し、公開されていれば物件の情報で上書きする
  - 欠番と判定した回数（一覧に書いたときの1回を含む）が `MISSING_CHECK_LIMIT` 回に達した行は再確認しない
  - 回数を減らすか空にすると、また再確認の対象になる

`START_ID` を変えたときは「連番取得の位置をリセット」を実行してください。

### 列構成を変えたとき（取り直し）

既存の行は自動で書き換わらないため、一覧を作り直して取り直します。

1. 「一覧」シートを削除する
2. 「① 初期設定」を実行する
3. 「連番取得の位置をリセット」を実行する
4. 「② 一覧を更新」または「自動更新を開始」を実行する（`START_ID` から取り直す）

## 注意

- 自動取得の前に、対象サイトの利用規約を確認してください。
- HTTP 429 / 403 が返った場合は自動で停止します。待ち時間（`SLEEP_MS`）を増やしてから再開してください。
- robots.txt を読み込めないときは、安全のため物件ページに一切アクセスしません。
